## 🧰 ToolConfig

ข้อมูลของ Tool สำหรับระบบ Inventory อยู่ที่:

```text
src/shared/Modules/ToolConfig.luau
```

เพิ่มข้อมูลใน `ToolConfig.Items` โดยชื่อ key ต้องตรงกับ `Tool.Name` (แนะนำให้ใช้เป็นรหัส ID เช่น `iron_sword`, `oak_wood` ส่วนชื่อแสดงผลกำหนดที่ `DisplayName`):

```lua
ToolConfig.Items = {
	oak_wood = {
		DisplayName = "Oak Wood",
		ItemType = "Resource",
		MaxStack = 10,
		Description = "ไม้สำหรับก่อสร้าง",
		Image = "rbxassetid://1234567890",
		IsDroppable = true,
	},

	health_potion = {
		DisplayName = "Health Potion",
		ItemType = "Consumable",
		MaxStack = 5,
		Description = "ยาเพิ่มพลังชีวิต",
		Image = "rbxassetid://9876543210",
		IsDroppable = false,
	},
}
```

### ฟิลด์ของ Tool

| ฟิลด์ | ชนิดข้อมูล | รายละเอียด |
| --- | --- | --- |
| `DisplayName` | `string` | ชื่อที่แสดงใน UI เปลี่ยนได้โดยไม่กระทบข้อมูลที่บันทึก |
| `ItemType` | `string` | ประเภทของไอเทม (`Weapon`, `Armor`, `Special`, `Consumable`, `Resource`) |
| `MaxStack` | `number` | จำนวนสูงสุดต่อ Stack |
| `Description` | `string` | คำอธิบายไอเทม |
| `Image` | `string` | รูปภาพไอเทม เช่น `rbxassetid://...` |
| `IsDroppable` | `boolean` | อนุญาตให้ผู้เล่นทิ้งไอเทมหรือไม่ |

### ค่า MaxStack เริ่มต้น

| ประเภท | จำนวนสูงสุด | แท็บใน UI |
| --- | ---: | --- |
| `Weapon` | 1 | `Weapons` |
| `Armor` | 1 | `Misc` |
| `Special` | 1 | `Tools` |
| `Consumable` | 5 | `Tools` |
| `Resource` | 10 | `Resources` |

สามารถกำหนด `MaxStack` เฉพาะ Tool เพื่อเขียนทับค่าเริ่มต้นได้

```lua
IronOre = {
	ItemType = "Resource",
	MaxStack = 64,
}
```

### ตำแหน่ง Tool ใน Roblox Studio

```text
ServerStorage
└── AllItems
    ├── oak_wood
    ├── health_potion
    └── iron_sword
```

Tool ที่สามารถถูกทิ้งและเก็บกลับได้ควรมี `Handle` อยู่ภายใน Tool

### ลำดับการอ่านข้อมูล

ระบบจะอ่านข้อมูลตามลำดับต่อไปนี้:

1. ข้อมูลใน `ToolConfig.Items`
2. Attribute ของ Tool เช่น `DisplayName`, `ItemType`, และ `IsDroppable`
3. Property ของ Tool เช่น `ToolTip` และ `TextureId`
4. ค่าเริ่มต้นของระบบ หากไม่มีข้อมูลระบุไว้

ข้อมูลที่บันทึกใน ProfileService จะเก็บเฉพาะ `Name` (ID ของ Tool), `Count`, `StackId` และ `Hotbar` ส่วนรายละเอียดแสดงผลจะถูกอ่านใหม่จาก `ToolConfig` ตอนโหลดข้อมูลผู้เล่น

## 💾 DataService

DataService ใช้ ProfileService และเปิด ProfileStore ชื่อ `PlayerData`

ข้อมูลเริ่มต้นของผู้เล่นประกอบด้วย:

```lua
{
	CurrentLevel = 1,
	CurrentExp = 0,
	ExpForNextLevel = 100,
	Cash = 0,
	Items = {
		Hotbar = {},
		NextStackId = 0,
		Stacks = {},
	},
	Plot = {},
	Pets = {
		MaxPetCapacity = 20,
		MaxEquippedCombat = 3,
		Instances = {},
		Incubators = {},
		BreedingPens = {},
	},
	Plants = {
		MaxActivePlanters = 24,
		Planters = {},
		HarvestStats = {},
	},
	LogInTimes = 0,
}
```

ฟังก์ชันที่ Service อื่นเรียกใช้:

- `GetProfile(player)` — คืนค่า Profile ปัจจุบันของผู้เล่น
- `WaitForProfile(player)` — รอจนกว่า Profile จะโหลดเสร็จ (คืนค่า `nil` หากผู้เล่นออกจากเกมก่อน)
- `OnBeforeProfileRelease(callback)` — ลงทะเบียนฟังก์ชันเพื่อบันทึกข้อมูลก่อนปล่อย Profile
- `AddExp(player, exp)` — เพิ่มค่าประสบการณ์และคำนวณการเลื่อนระดับเลเวลของผู้เล่นอย่างปลอดภัย

## 🎒 Inventory System (Server & Client)

### ฝั่ง Server (`src/server/Services/DataService/InventoryService.luau`)
- ตรวจจับ Tool ที่เข้า/ออกจาก `Backpack` และ `Character` อัตโนมัติ
- รวม Tool ที่มีชื่อเดียวกันเป็น Stack (สูงสุด 20 Stacks ต่อผู้เล่น)
- จัดการ Hotbar 10 ช่อง (`Slot1` - `Slot10`) และตั้งค่าไอเทมเข้า Hotbar อัตโนมัติ (ยกเว้นประเภท `Armor`)
- รักษาไอเทมในกระเป๋าเมื่อตัวละครตายและเกิดใหม่ (`Respawning`)
- ทิ้ง Tool ลง `Workspace` และสร้าง `ProximityPrompt` ให้เก็บกลับได้
- มีระบบ Rate Limiting ป้องกันการยิง Packet รัวจากฝั่ง Client
- มี API สำหรับเชื่อมต่อกับระบบอื่น:
  - `HasItem(player, itemName): boolean` — ตรวจสอบว่าผู้เล่นมีไอเทมหรือไม่
  - `ConsumeItem(player, itemName): boolean` — หักไอเทมออกจากกระเป๋า 1 ชิ้น
  - `GiveItem(player, itemName): boolean` — สร้างไอเทมจาก `ServerStorage.AllItems` เข้ากระเป๋าผู้เล่น

### ฝั่ง Client (`src/client/StarterPlayerScripts/InventoryClient.luau`)
- สร้างเป็น Knit Controller ชื่อ `"InventoryClient"` (`Knit.CreateController`) และเริ่มต้นทำงานผ่าน `Knit.Start()` ใน `main.client.luau`
- ปิด CoreGui Backpack เดิมของ Roblox และจัดการ State ของกระเป๋าฝั่งผู้เล่น (`Data`, `SelectedStackId`, `IsOpen`, `LastError`)
- ใช้รูปแบบ Observer (`Subscribe` / `notify`) เพื่อแจ้งเตือน React UI ทุกครั้งที่ข้อมูลอัปเดต
- รับอินพุตปุ่ม `B` สำหรับเปิด/ปิดกระเป๋า และปุ่มตัวเลข `1`-`0` สำหรับถือไอเทมใน Hotbar

## 🏗️ PlotService (Server & Client)

ระบบสร้างและวางสิ่งของในพื้นที่ส่วนตัวของผู้เล่น แบ่งการทำงานดังนี้:

| `PlotService/PlotController.luau` | Client | Knit Controller (`"PlotController"`) รอรับ Plot จาก Server และผูกปุ่ม `F` เพื่อเปิด/ปิดโหมดวางสิ่งของ |

### การทำงานร่วมกับระบบ Inventory
- **การวางสิ่งของ (`PlotManager.place`):** หากชื่อสิ่งของใน `ReplicatedStorage.PlaceableObjects` มี `Tool` ชื่อเดียวกันอยู่ใน `ServerStorage.AllItems` ระบบจะตรวจสอบว่าผู้เล่นมีไอเทมนั้นในกระเป๋าหรือไม่ และหักไอเทมออก 1 ชิ้นเมื่อวางสำเร็จ
- **การลบสิ่งของ (`PlotManager.delete`):** เมื่อผู้เล่นกด `X` ลบสิ่งของใน Plot หากสิ่งของนั้นมี `Tool` คู่กันใน `ServerStorage.AllItems` ระบบจะคืนไอเทมกลับเข้ากระเป๋าผู้เล่น 1 ชิ้น (หากกระเป๋าเต็มจะไม่อนุญาตให้ลบเพื่อป้องกันไอเทมสูญหาย)

| `shared/Modules/ToolConfig.luau` | Shared | เพิ่มข้อมูลไอเทมเกษตร 12 ชิ้น (กระบะปลูก, สปริงเกลอร์, บัวรดน้ำ, ปุ๋ย, เมล็ดพันธุ์ และผลผลิต) |

### การทำงานร่วมกับระบบอื่นในเกม (Ecosystem Synergy)
- **ร่วมกับ `PlotService`:** วางและบันทึก `wooden_planter`, `fertile_garden_bed` และ `hydro_sprinkler` พร้อม `ObjectId` ถาวรผ่าน `PlotStorage`, ลงทะเบียน `RegisterDeleteValidator` ป้องกันการลบกระบะที่มีพืชกำลังปลูกอยู่ และเชื่อม `OnPlotLoaded` เพื่อรัน Offline Catch-up และผูก `ProximityPrompt` อัตโนมัติ
- **ร่วมกับ `InventoryService`:** ตรวจสอบและหักเมล็ดพันธุ์/ปุ๋ย (`HasItem` / `ConsumeItem`), ตรวจการมี `watering_can` ในกระเป๋าขณะรดน้ำ และมอบผลผลิตเข้ากระเป๋าแบบปลอดภัย (`GiveItem`) พร้อม Rollback หากกระเป๋าเต็มตั้งแต่ชิ้นแรก (และรองรับ Partial Harvest เมื่อเหลือที่ว่างบางส่วน)
- **ร่วมกับ `PetService`:** ผลผลิตจาก `berry_seed` (`berry_feed`) และ `golden_apple_seed` (`golden_apple`) สามารถนำไปให้อาหารสัตว์เลี้ยงได้ทันที และเมื่อมีสัตว์เลี้ยงสายธรรมชาติ (`sprout_slime` หรือ `flora_guardian`) เดินอยู่ใน Plot (`State == "InPlot"`) จะมอบ **Nature Pet Aura** เพิ่มความเร็วเติบโตของพืชอีก `+10%` (`NaturePetAuraBonus`)

## 🛡️ AdminSystem (ระบบผู้ดูแลระบบและหน้าต่างควบคุม)

ระบบผู้ดูแลระบบทำงานแบบ Server-Authoritative ร่วมกับ **Knit**, **ByteNet (`AdminNetwork`)**, **DataService**, **InventoryService** และ **ToolConfig**:

| ไฟล์ | ฝั่ง | หน้าที่ |
| --- | --- | --- |
| `shared/Modules/AdminConfig.luau` | Shared | ตั้งค่าสิทธิ์แอดมิน (`AllowCreator`, `AllowStudioAccess`, `AdminUserIds`, `GroupConfig`), ช่วงความเร็วเดิน (`MinWalkSpeed = 4`, `MaxWalkSpeed = 120`, `SpeedPresets`), จำนวนเสกสูงสุดต่อครั้ง (`99`) และขนาด Audit Log (`50`) |
| `shared/Modules/Types.luau` | Shared | ประกาศชนิดข้อมูล `AdminPlayerSummary`, `AdminStackItem`, `AdminPlayerDetail`, `AdminAuditEntry`, `AdminToastInfo` |
| `server/Services/AdminService/Server.luau` | Server | Knit Service (`"AdminService"`) รับคำสั่ง `AdminNetwork`, ตรวจสิทธิ์ทุก Packet, Rate Limiting (Read + Token Bucket สำหรับ Mutation), Action Lock และคงค่า WalkSpeed เมื่อตัวละครเกิดใหม่ |

| `server/Services/AdminService/AdminActionExecutor.luau` | Server | สร้างสรุป/รายละเอียดผู้เล่น, เสกไอเทมผ่าน `InventoryService.GiveItem`, ปรับ WalkSpeed, ตรวจสอบไอเทมที่ขาดใน `ServerStorage.AllItems` และบันทึก Audit Log |
| `client/StarterPlayerScripts/AdminService/AdminController.luau` | Client | Knit Controller (`"AdminController"`) เก็บ State แบบ Observer, ซิงก์สิทธิ์จาก Server และผูกปุ่มลัด `M` (เฉพาะผู้ดูแลระบบ) |
| `client/StarterPlayerScripts/UI/AdminPanelFrame.luau` | Client | หน้าต่าง `ADMIN CONTROL PANEL [M]` ประกอบด้วย 4 แท็บ: `Players` (ตรวจข้อมูล/กระเป๋าผู้เล่น), `Item Spawner` (ค้นหา/กรองหมวดหมู่และเสกไอเทม), `Self Speed` (Preset/กำหนดเอง) และ `Audit Log` |
| `client/StarterPlayerScripts/UI/Components/AdminItemSpawnCard.luau` | Client | การ์ดรายการไอเทมสำหรับเสกให้ตัวเองหรือผู้เล่นเป้าหมาย พร้อมแจ้งเตือนและปิดปุ่มหากขาด Tool ใน `ServerStorage.AllItems` |

### การตั้งค่าสิทธิ์และไอเทมสำหรับ AdminSystem
- **`AdminConfig.AdminUserIds`**: เพิ่มรายชื่อแอดมินด้วย `UserId` (ตัวเลข) เช่น `[123456789] = true` ใน `src/shared/Modules/AdminConfig.luau` (ห้ามใช้ Username เพราะผู้เล่นเปลี่ยนชื่อได้)
- **`AdminConfig.GroupConfig`**: กำหนด `GroupId > 0` และ `MinAdminRank` (ค่าเริ่มต้น `250`) เพื่ออนุญาตผู้ดูแลจากยศใน Roblox Group อัตโนมัติ (นอกจากนี้เจ้าของแมพจะได้รับสิทธิ์อัตโนมัติเมื่อ `AllowCreator = true`)
- **`AdminConfig.AllowStudioAccess`**: ค่าเริ่มต้นคือ `true` เพื่อให้ทดสอบหน้าต่าง Admin ใน Roblox Studio ได้ทันทีโดยไม่ต้องเพิ่ม UserId
- **`ServerStorage.AllItems`**: ไอเทมที่จะเสกผ่านแท็บ `Item Spawner` ต้องมีทั้งข้อมูลใน `ToolConfig.Items` และมีโมเดล `Tool` ชื่อตรงกันอยู่ใน `ServerStorage.AllItems` หากขาดตัวใด ระบบจะแจ้งเตือนใน Console ฝั่ง Server และขึ้นป้าย `[ขาด Tool ใน Studio]` บนการ์ดไอเทมให้ผู้ดูแลระบบเห็นทันที

## 🌐 Network (ByteNet)

ระบบสื่อสารระหว่าง Server และ Client ทั้งหมดใช้ **ByteNet** (Binary Serialization) ผ่านไฟล์:

```text
src/shared/Modules/Network.luau
```

Namespace ที่ใช้งานอยู่:

- **`InventoryNetwork`**
  - `Request` — Client ขอข้อมูลกระเป๋าเริ่มต้น
  - `Update` — Server ส่งข้อมูลกระเป๋า (`ClientInventory` Struct) ให้ Client
  - `EquipToHotbar` / `UnequipFromHotbar` — สวมใส่หรือถอดไอเทมออกจากช่อง Hotbar
  - `HoldItem` / `UnholdItems` — ถือหรือเก็บ Tool ในมือตัวละคร
  - `DropItem` — ทิ้งไอเทมลงพื้น
  - `Error` — ส่งข้อความแจ้งเตือนข้อผิดพลาดไปแสดงบน `ErrorToast`
- **`PlotNetwork`**
  - `Request` / `Ready` — ขอและส่ง Instance ของ Plot ประจำตัวผู้เล่น
  - `TryPlace` — ส่งชื่อสิ่งของและ `CFrame` เพื่อขอวางใน Plot
  - `TryDelete` — ส่ง Instance เป้าหมายเพื่อขอลบออกจาก Plot
- **`PetNetwork`**
  - `RequestSync` / `SyncState` — ขอและซิงก์ข้อมูลสัตว์เลี้ยง, เครื่องฟักไข่ และคอกผสมพันธุ์ทั้งหมดของผู้เล่น
  - `FeedPet` / `TriggerEvolve` — ส่งคำสั่งให้อาหารและวิวัฒนาการสัตว์เลี้ยง
  - `SetPetState` — สลับโหมดสัตว์เลี้ยง (`InPlot` / `Equipped` / `Stored`)
  - `StartIncubation` / `ClaimHatchedPet` — เริ่มฟักไข่และรับสัตว์เลี้ยงเมื่อฟักเสร็จ
  - `StartBreeding` / `ClaimBreedingEgg` — เริ่มผสมพันธุ์และรับไข่เข้ากระเป๋า
  - `OpenModal` — Server สั่งเปิดหน้าต่าง Incubator/Breeding เมื่อกด `ProximityPrompt`
  - `PetVisualEvent` *(Unreliable)* — ส่งสัญญาณเล่น VFX (`Eat`, `Evolve`, `Attack`, `Hatch`) บนฝั่ง Client
  - `NotifyToast` — ส่งข้อความแจ้งเตือนผลลัพธ์ (สำเร็จ/ผิดพลาด) ไปแสดงบน `ErrorToast`
- **`PlantNetwork`**
  - `RequestSync` — Client ขอข้อมูลแปลงปลูกและสถิติการเก็บเกี่ยวทั้งหมดจาก Server
  - `SyncState` — Server ซิงก์ข้อมูล `Planters` (`PlanterStateStruct`) และ `HarvestStats` (`HarvestStatEntryStruct`) ทั้งหมดให้ Client
  - `SyncSinglePlanter` — Server ส่งอัปเดตเฉพาะแปลงเดียวแบบ Delta (`ObjectId`, `IsEmpty`, `Planter?`, `UpdatedStat?`)
  - `PlantSeed` — ส่งคำสั่งปลูกเมล็ดพันธุ์ (`ObjectId`, `SeedItemId`) ลงในกระบะปลูก
  - `WaterPlant` — ส่งคำสั่งรดน้ำให้แปลงปลูก (`ObjectId`)
  - `ApplyFertilizer` — ส่งคำสั่งใส่ปุ๋ยบำรุงแปลงปลูก (`ObjectId`, `FertilizerItemId`)
  - `HarvestCrop` — ส่งคำสั่งเก็บเกี่ยวผลผลิตเมื่อพืชโตเต็มวัย (`ObjectId`)
  - `UprootPlant` — ส่งคำสั่งถอนต้นไม้ออกจากแปลงปลูก (`ObjectId`)
  - `OpenPlantModal` — Server สั่งเปิดหน้าต่าง `PlantModal` (หรือทำทางลัดตาม Tool ที่ถืออยู่) เมื่อผู้เล่นกด `ProximityPrompt`
  - `PlantVisualEvent` *(Unreliable)* — ส่งสัญญาณเล่น VFX (`Plant`, `Water`, `Fertilize`, `Mature`, `Harvest`) ตามตำแหน่ง `WorldPos` บนฝั่ง Client
  - `NotifyToast` — ส่งข้อความแจ้งเตือนผลลัพธ์ของระบบเพาะปลูก (สำเร็จ/ผิดพลาด) ไปแสดงบน `ErrorToast`
- **`AdminNetwork`**
  - `RequestAccess` — Client ขอตรวจสอบสิทธิ์แอดมินและค่าความเร็วเดินเริ่มต้นจาก Server
  - `SyncAccess` — Server ส่งสถานะสิทธิ์ (`IsAdmin`), ความเร็วเดินปัจจุบัน (`CurrentWalkSpeed`) และรายชื่อไอเทมที่ขาดใน Studio (`MissingStudioItems`, ส่ง `{}` ให้ผู้เล่นทั่วไป)
  - `RequestPlayerList` — แอดมินขอรายชื่อผู้เล่นออนไลน์และประวัติ Audit Log ล่าสุด
  - `SyncPlayerList` — Server ส่งรายชื่อผู้เล่น (`AdminPlayerSummaryStruct`) และประวัติคำสั่ง (`AdminAuditEntryStruct`) ให้แอดมิน
  - `InspectPlayer` — แอดมินส่ง `TargetUserId` (`float64`) เพื่อขอดูรายละเอียดและไอเทมในกระเป๋าของผู้เล่นเป้าหมาย
  - `SyncPlayerDetail` — Server ส่งข้อมูลเชิงลึกของผู้เล่นเป้าหมาย (`AdminPlayerDetailStruct` พร้อมรายการ `AdminStackItemStruct`)
  - `GiveItem` — แอดมินส่งคำสั่งเสกไอเทม (`TargetUserId`, `ItemId`, `Amount`) ให้ตัวเองหรือผู้เล่นเป้าหมาย
  - `SetSelfWalkSpeed` — แอดมินส่งคำสั่งปรับความเร็วเดินของตัวเอง (`WalkSpeed`, ช่วง 4–120)
  - `NotifyToast` — Server ส่งข้อความแจ้งเตือนผลลัพธ์ (สำเร็จ/ผิดพลาด หรือแจ้งผู้รับไอเทม) ไปแสดงบน `ErrorToast`
